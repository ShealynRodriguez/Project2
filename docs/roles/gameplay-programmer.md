# Gameplay Programmer

who: 

You own how the game plays and feels. You turn the team's ideas into actual gameplay.

## What you'll do
- Choose the game engine with the team
- Set up the shared GitHub repository
- Build player movement
- Implement the core game mechanic
- Add enemies, obstacles, or challenges
- Create win and lose conditions

## Timeline
- Weeks 1-2: Set up the engine and GitHub repository. Help the team create the design document.
- Weeks 2-3: Build a rough gameplay prototype using placeholder art. This is your most important early milestone, so get something playable on screen as soon as possible.
- Midway checkpoint: Your prototype becomes the foundation of the demo. Focus on stable and playable rather than fancy.
- Later weeks: Tune difficulty, improve game feel, and fix gameplay bugs.

## Tips
- Commit your work to GitHub small and often.
- Teach the team the basic Git workflow early.
- Get something moving on screen during the first week.
- Build the basic version first, then improve it.
